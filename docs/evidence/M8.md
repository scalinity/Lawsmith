## Design plan (two passes, reviewed against SPEC §11 and AC1–AC9)

**Pass 1.** Palette and type are the project's own tokens, not a new direction: warm-ink shell `#141311`, card `#211f1c`, text `#f3f0ea`, teal `#55aaa4` for what you edit and select, lavender `#c58ae5` for the recorded past, danger `#e0806b`; system sans for controls, the serif only for the scene title and the replay title, mono only for numbers and diagnostics. The memorable element is the viewport and its laws. Layout: one transparent grid over the full-window canvas; panels take the pointer, the gaps belong to the canvas.

```
 ●●●   [drag band: empty, invisible]                  [Undo Redo | Move Rotate Adjust | Frame Reset view]
┌ Scene card ──────────┐                                       ┌ context column ───────────┐
│ Title        Hide laws│                                      │ simulation error (if any) │
│ state · New Open Save │                                      │ recording / replay         │
│ [Open an example…]    │         VIEWPORT                     │ two futures (if any)       │
│ │ invitation          │     laws named over supports        │ explained body             │
├ Laws / inspector ─────┤                                      └───────────────────────────┘
│ list, details, Motion │                                          [what to draw]
│ Display: scale        │                                          [Play Step Reset  tick]
└───────────────────────┘ diagnostics
```

**Pass 2 (review against the brief).** Rejected: a titlebar band or Build/Simulate/Explore header (AC9, SPEC §11.1); moving the law inspector into a new right column, because at 200% two side columns plus the inspector would leave almost no viewport and every accepted native workflow reaches the inspector through the scrolling left panel; a settings framework or persisted preference store. Kept from pass 1: a scene card that never scrolls (fixes the M2/M5 displaced file actions), one stacked context column (fixes M7's banner over the comparison card), a dock, a collapse control, and law names as the one new visible element, set in each law's own ink with a shell halo, underlined when selected and reading "off" when disabled. No new decorative motion; under Reduce motion the camera's orbit glide stops.

**Recorded relationship decision.** SPEC §11.1 describes a contextual right panel for the selected law's parameters or the selected body's explanation. The explanation is on the right; law parameters stay directly beneath the Laws list, as accepted since M1, and the whole column collapses. This is flagged for review and owner judgement; it is not a change of SPEC.

## Known limitations and review risks

- Compare from here now starts A immediately. This alters M7's visible flow (not its semantics) and moved the P3 600-tick construction trigger from a button to the fork; the M7 scenarios were adapted accordingly and must be rerun.
- The CSS conversion touches every interface length; only native captures can show regressions. All accepted scenarios read positions from layout readbacks, but `m7-compare` and `m7-r1-panel` scroll at a fixed point (25, 350) assumed to lie over the panel.
- Law names add per-frame DOM positioning (writes only on change, no forced layout); P0–P3 must be remeasured with them on.
- A repeated click on a selected law that overlaps another now selects the other.
- Tab reaching buttons depends on macOS Keyboard navigation (WebKit behavior); `m8-keyboard` uses ⌥⇥ so it neither depends on nor changes the setting.
- Interface Scale is session-local.
- Examples-menu selection in the native pop-up is driven by type-select and Return; the first native run will show whether that is reliable.
