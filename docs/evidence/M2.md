## Scene format (schema 1)

```json
{ "format": "lawsmith.scene", "schemaVersion": 1, "requiredCapabilities": [...],
  "semantic": { "units": "m-kg-s", "seed", "simulation", "bodies", "emitters", "fields" },
  "presentation": { "camera"?, "arrows", "laws": [{ "id", "label", "color", "visible" }] },
  "metadata": { "title", "description"? } }
```

- **Capabilities** this build implements: `region.box.v1`, `primitive.directional.v1`, `emitter.xorshift32.v1`. An unknown one is rejected before the scene is read; a law kind the SPEC defines but this build lacks (`vortexY`, `sum`, …) is rejected with its capability named; a used but undeclared capability is rejected. Nothing is dropped or substituted.
- **Strictness:** unknown and missing properties are rejected at their path; numbers must be finite (`1e400` is rejected); counts, IDs (64 characters, ASCII letters, digits, `_`, `-`), text (8192 characters), file size (5 MiB, checked before parsing) follow SPEC §15.2; IDs are unique across bodies, emitters and laws.
- **Canonical form:** keys sorted by UTF-16 code unit, entity arrays and capabilities sorted, full-precision shortest round-trip numbers, negative zero written as `0`, plain-value arrays on one line, a trailing newline. Capabilities are recomputed on write.
- **Not serialized:** live body state, tick, engine bytes, selection, hover, gesture state, timings. Camera framing is captured at save, never as a document edit.
- **Choices:** only an identity emitter rotation is accepted (SPEC §5.3 gives emitters a pose without defining its rotation; finding 5). Dynamic bodies must be spheres in this build. No migration exists, because no prior schema exists.

## Native I/O and recovery architecture

- **Authority.** Dialogs run in Rust through the official plugin; each result becomes an opaque session-local token. The frontend holds tokens and display names, never paths, and can write only through a token a dialog issued. Imported JSON and recovery envelopes never carry paths. Tokens do not survive a restart, so recovered work chooses its destination again.
- **Reads** are bounded at 5 MiB before and during reading (`take(limit+1)`, so a growing file cannot pass) and must be strict UTF-8.
- **Replacement** (`replace_file`): a unique temporary sibling created exclusively; complete write; `sync_all` (F_FULLFSYNC on macOS); close; `rename` over the target; directory `sync_all`. The old file is never truncated; a failure before the rename removes the temporary. A read-only target is refused instead of replaced; a symlinked target is resolved; permissions carry over. A failed directory sync after the rename is reported as `uncertain`, which keeps the document dirty. Power-loss durability beyond what APFS gives these calls is not claimed.
- **Workflows** are exclusive: a conflicting Open/Save/Save As/New is refused and logged. A save captures the settled document at one revision, binds a new destination only after its write succeeds, marks only that revision saved, and awaits retirement of its recovery copy. A reply for an older generation changes nothing.
- **Open** is transactional: bounded read → parse and validate → one unstepped candidate world with its prepared view → guard → commit, which only swaps them in; any failure, cancellation or exception before commit disposes the candidate and replaces nothing. If the guard saved, the chosen file is read again before commit.
- **Recovery** files live in `app_local_data_dir/recovery` (`LAWSMITH_RECOVERY_DIR` isolates QA runs). The writer is debounced (500 ms), skips gestures in progress and clean documents, and serializes writes and retirements. The store keeps the current and one previous snapshot and writes the new one completely before rotating. Only a current that launch validation accepted, or that this session wrote, rotates into previous; a corrupt current is replaced in place, so it never displaces a valid fallback. The store rejects writes not newer than the last or inside a retired range, and records retirement only after the files are gone. Launch recovery holds the session from its first moment: edits are frozen, and Open, Save, Save As, New and recovery writes are refused, until the lookup finds nothing to offer or the user recovers or discards the offer. The launch Discard removes only the earlier session's snapshots.
- **Guard.** Close (window button, ⌘W), ⌘Q, the Quit menu item, and `terminate:` (Dock Quit, logout, an Apple Event quit) all reach one frontend guard once it reports ready. Tauri's default macOS Quit sends `terminate:`, which TAO 0.37.1 does not intercept, so the menu replaces it with a Lawsmith item, and `applicationShouldTerminate:` is added to TAO's delegate class at launch (finding 2). That method lets termination proceed at once only when the document is clean and the recovery store holds no snapshot and is idle (checked without waiting on its lock); that answer also closes the store to further writes, so nothing can be left behind. A clean Lawsmith with nothing to retire therefore never blocks a logout. Otherwise it cancels termination and runs the guard, whose clean branch retries a pending or failed retirement and then exits or refuses. The guard pauses, settles, freezes edits and offers Save, Don't Save (⌘D) or Cancel (Esc); Save goes through Save As when unbound; Discard is staged and retires recovery only when the transition commits; exit waits for recovery work to settle; requests coalesce.

## Findings

1. **Dialog plugin does not build against the pinned Tauri core** (gate above). Vendored with the upstream one-line fix by owner decision. Owner: the next dependency update; drop the patch once an official fixed release is qualified.
2. **Default Quit cannot be intercepted.** Tauri's predefined Quit and the Dock's Quit send `terminate:`, and TAO 0.37.1's delegate does not answer `applicationShouldTerminate:`. Resolved in M2 by a Lawsmith Quit item and by adding that delegate method to TAO's class at launch through the Objective-C runtime; the shell logs `terminateGuard: true`. A TAO upgrade that adds its own method would make the addition fail (logged false) rather than collide. Owner: whoever next changes Tauri/TAO; recheck the log line.
3. **Synthetic drag releases are sometimes lost** (M0 finding 1's synthetic-input behavior). M1's reconciliation ended them (`stale-buttons`); when it did not, the harness re-sent the release. Real-trackpad behavior is M1's owner-checked result. Informational.
4. **macOS automation facts that shaped the harness.** WKWebView exposed no web content to Accessibility in this configuration; cliclick's named keys (Return, Escape, Tab) do not reach WKWebView or AppKit panels while its typed text and chords do; synthetic Return and Escape do not reach the Go to Folder sheet; System Events can report `loginwindow` frontmost while a panel is open; a quit Apple Event is held while an alert is up. Informational.
5. **SPEC §5.3 does not define emitter rotation.** Schema 1 accepts only the identity (any representation whose canonical vector part is zero, stored as the exact identity) so no file carries an ignored rotation. Owner: a SPEC decision before emitters become authorable (M8 examples at the latest).
6. **Duplicate JSON keys** follow `JSON.parse` (last wins) rather than being rejected. Deterministic, low risk. The independent review found it consistent with the current SPEC text; unchanged.
7. **Cold first frame is about 4.6 s** on a new bundle's first launch (`ready.firstFrameMs`); M0 finding 5, owned by M9. Not an M2 gate.
8. **The lower precise fields scroll within the panel at smaller heights.** At 1280×800 with one law, Strength and Fade sit below the panel's visible area ([capture](m2/p0-1280x800.png)); at the built-in display's 734 px content height with two or more laws, Rotation and Half extents do too. All stay reachable by scrolling the panel. Owner: M8's interface pass.

9. **`terminate:` answers on the frontend's last reported dirty state.** An edit made within one IPC round trip before Dock Quit, logout or a quit Apple Event (with no recovery snapshot yet, as the write is debounced) can be lost; Close, ⌘W, ⌘Q and the Quit item always run the guard. The window is the cost of answering a clean logout without interrupting it; routing every `terminate:` through the guard would close it but make every logout report Lawsmith as interrupting. Informational; owner may choose.
10. **Earlier-session recovery files that fail validation are left in place.** While they remain, the store is not empty, so Dock Quit or logout of a clean Lawsmith runs the guard, which exits without asking but makes macOS report the logout as interrupted. A save retires them. Low.
11. **A failed launch lookup answers launch recovery with nothing offered** and is logged, so the session stays usable; a later save would then retire those files. The native lookup reports unreadable files as slot states, so only a failure of the command itself (a task panic) takes this path. Informational.
