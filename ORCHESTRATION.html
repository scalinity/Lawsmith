    One unit, one session

    A session owns one unit and ends at its close-out. The next unit starts in a fresh session from main, so each session’s context and evidence stay attributable to one candidate.

      git switch main && git pull --ff-only on a clean tree.

      git worktree list and this page show what other sessions own.

      Read the sources of truth, then branch for the unit: m1, m1-pointer-guard.

    2. 2

      Work

      Small coherent commits, staged by name.

    3. 3

      Review

      Address every finding. A fix closes it once re-verified. A fix that would break SPEC, MILESTONES or an owner decision is answered in writing and surfaced to you instead.

    4. 4

      Close out

      Default close-out follows the seven steps below. M7 remediation ends at a clean, pushed m7 candidate and a targeted GPT-6 Pro prompt. Merge, branch deletion and M8 are unauthorized in this unit.

    5. 5

      You

      Run the owner checks the unit left pending.

      Mark the gate ACCEPTED, or send it back. Only you can.

    Next unit: a fresh session from main
    1. Verified

      Every required check for the unit ran, and its result is in docs/evidence/M<n>.md.

    2. Realigned

      This page reflects the unit’s outcome: strip state, eligibility lines, open threads.

    3. Committed

      git status is clean on the branch.

    4. Merged

      git switch main && git pull --ff-only && git merge --ff-only <branch>. If that fails: --no-ff, resolve keeping both sides’ intent, then re-run npm run typecheck and npm run build on main.

    5. Pushed

      git push origin main, then git rev-parse main equals git rev-parse origin/main.

    6. Branch discarded

      Only once git merge-base --is-ancestor <branch> origin/main succeeds and no worktree or session uses it. If git branch -d refuses, keep the branch and report it.

    7. Reported

      The pushed main SHA, the discarded branch, and what changed on this page.

    • Use absolute paths and real identifiers. Never write “as discussed” or “the file we changed”.
    • Give every instruction that is not self-evident its reason, so a session cannot talk itself out of it.
    • State refusals as plainly as tasks: do not start the next milestone; do not mark it complete unless every criterion holds.
